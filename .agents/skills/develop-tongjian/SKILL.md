# 通鉴网站开发

## 开始工作

1. 读取 [设计约定](references/design-contract.md) 和
   [项目现状](references/project-context.md)，确认最新用户指令。
2. 优先检查用户当前工作目录中的 `AGENTS.md`、源码、数据和版本状态。
   将当前项目视为权威；不要用技能快照覆盖后续开发。
3. 没有现有源码时，使用 `scripts/bootstrap_project.py --target PATH`
   从 `assets/project-baseline` 恢复已确认的第一卷原型。
   仅向不存在或为空的目录复制；不要复制生产身份或凭据。
4. 继续已有 Sites 网站时，调用现有 Sites 工作流打开其源码并保留身份、
   权限；参考项目现状定位原站。使用本地 Codex 时继续当前项目的开发
   和部署方式。没有 Sites 能力不妨碍本地开发。

## 实现约定

- 以逐年年表为入口，展示每一年及其记事标题。点击事件进入整页阅读，
  定位到对应段落；返回年表恢复浏览位置。
- 在桌面端同一行放古文和白话，使用共同滚动区域；手机端同组内上下排列。
  保留对照、仅原文、仅白话、注释开关、字号、年份切换和搜索。
- 沿用已确认的纸色、墨绿、简洁边框和排版。
  不主动加入双页书卡片、中央圆形编号、年份水印或字体美化。
- 使用原始文件内容。区分古文、胡注/校勘、白话和史家评论。
  不将自动生成的白话标成柏杨译文；不凭文件名宣称版本已鉴定。
- 先读 [数据处理](references/data-pipeline.md) 再处理 EPUB 或新增卷。
  保留空白年份、追叙所属位置、来源差异和原文异常提示。
- 先读 [数据结构](references/data-model.md) 再改 schema、索引或对齐逻辑。
  保持稳定的年份与段落定位，不能按数组位置直接匹配不同版本。
- 用户请求优先于这些约定；没有新请求时，避免无关重构、框架迁移和视觉改版。

## 验证与交付

用户要求部署、发布、更新服务器版本或查看访问统计时，读取 [服务器发布](references/server-deployment.md)。
仅本地开发不自动发布；保存发布流程不表示授权执行发布。

运行 `scripts/validate_volume.py --data PROJECT/dist/volume1.json` 检查数据。
对数据处理改动核对原文可重建、翻译完整性、对齐覆盖和来源差异。
对导航改动检查独立阅读页、事件锚点、返回位置、前后年份和浏览器历史。
修改脚本时实际执行；只做视觉微调时不添加镜像实现的测试。
使用浏览器验证能力可用时检查桌面与手机排版；不可用时如实报告限制，
不要把 DOM 模拟或语法检查称为视觉验收。
按现有项目方式保存、发布或提供可运行结果；不要假装已部署到用户服务器。

## 资源

- `assets/project-baseline/`：回退美化后的第一卷可运行原型，含真实数据。
- `scripts/bootstrap_project.py`：向空目录恢复快照。
- `scripts/extract_volume1.py` / `scripts/align_volume1.py`：第一卷专用提取与匹配。
- `scripts/extract_volume2.py` / `scripts/align_volume2.py`：第二卷专用提取与匹配。
- `scripts/validate_volume.py`：验证逐年数据及对照覆盖。
- [延伸开发](references/next-development.md)：第二卷现状与后续卷扩展步骤。

将快照用于恢复或验证；不要把“目前只支持第一卷”的脚本误当成全书工具。
