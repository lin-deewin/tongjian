# PDF 保真改编文章

把用户已经认可的稿件转换成适合连续阅读的文章。默认保留它的具体场景、叙事节奏、论证、图表和出处，按用户要求清理教学组织形式。用户明确要求重写、删节或增加主持与练习时，以新指令为准；不要将“改成文章”自行扩大为整篇重写。

## 确定底稿与范围

- 以用户指定、认可的那一版为内容基准；当前网页或其他扩写稿不自动优先。区分“保真改编”“扩写”“重新创作”。
- 用户认可底稿后只说“改写一下／改成文章”，仍以保真编辑为起点；只有明确要求整体重写、重新组织或扩写时才扩大改动。
- 有 Markdown、JSON 等可编辑源稿时，先与实际 PDF 的正文、引文、图表标题和出处核对。源稿吻合后再用它生成文章；无法确认时回到 PDF，不凭同名文件认定版本一致。
- 没有源稿时按章节整理可追溯的原文块。规范空白、软换行等提取噪声，保留措辞、标点、数值与引用；扫描 PDF 需要核对 OCR，不将识别错误当成原稿。
- 只要求文章或网页时保留源 PDF。需要改 PDF 本身时使用可用的 PDF 技能，完成相应渲染验收。

## 逐块处理

为正文、引文、图表、来源与教学安排分别记录“保留／移除／最小修改”的决定。使用简单差异表即可；有结构化源稿时可沿用块 ID 和校验值，无须为普通文本另建复杂系统。

先复制保留块的原文，再处理允许的删除与连接修改。不要在重新叙述中凭记忆恢复内容，也不要默默换同义词、合并段落时省句。保留块应逐段一致；任何字句变化都列入修改记录。每个源块都应有去向，图表不能因“文章化”变成未说明的省略。

| 内容 | 默认处理 |
| --- | --- |
| 故事、背景、人物处境、论证与结论 | 保留原文和顺序；不要以抽象解释替换具体场景 |
| 心理推断的限定、其他解释、经验边界 | 完整保留，不能只留下更强硬的结论 |
| 原文短引、注释、出处与来源链接 | 保留对应关系，检查目标与署名 |
| 关系图、信息路径图、时间线和比较表 | 保留实质内容、标题、标签和说明；按阅读媒介调整布局 |
| 主持流程、会议时间表、分组说明、作答指令和空白答题区 | 用户要求纯文章时移除 |
| “参考分析／答案”标题下的内容 | 先辨别：与案例有关的论证保留；仅服务被删除练习的模拟情境与答案可移除 |
| 页码、册／文称谓及删除题目后悬空的指代 | 最小修改，记录原句、改句与理由 |

逐块处理后，单独检查被删除题目附近的分析段：“可以。”“前两句”“这个答案”等是否失去指向。不能为了逐字保留而留下悬空答案；这类句子需要主动作最小修改，并登记。遇到这类指代，先读 [最小改编示例](references/minimal-edits.md)，补回必要的命题，不借衔接之名重写整个分析段。仍有悬空指代时，不能把机械校验通过报告成整体验收通过。

## 保留阅读吸引力与深度

- 保留原稿的故事入口、转折与疑问，让分析落在人物当时的信息、约束和选择上。
- 用已有证据说明判断的缺口。不要为显得更深而普遍加长段落、重复原则或新增未经核实的心理和因果解释。
- 必要的连接句应帮助原段独立成立。用户要求少量深化时，补在具体关键处，明确区分原稿与新增内容。
- 通鉴专题需要核验事实时，结合可用的 [通鉴研究技能](../tongjian-research/SKILL.md)；其他领域采用相应来源，不硬套通鉴案例。

## 适配与验收

沿用目标网站已有的设计。图可在桌面横排、手机竖排，但箭头方向、实线／虚线意义、关系状态、数值和图注不能变化。表格与来源在手机上应可读，不能仅把 PDF 页面缩成图片。

交付前核对：

1. 保留的叙事段落和引文与底稿逐段一致；列出所有移除及修改，确认没有未经说明的实质变化。源稿本身有事实错误时，核实后单独修正、说明，不为保真保留错误。
2. 分析、限定与边界未因删掉“参考答案”标题而误删；图表的文字、方向和出处一致。
3. 检查可见正文中是否仍残留用户要求移除的组织、作答与填空内容。
4. 网页交付检查桌面与手机排版、目录、原文链接和返回路径。保持有用的旧锚点，不因内部名称带 `practice` 就破坏分享地址。

有 `pages / blocks` 结构化源稿时，使用 [校验工具说明](references/verification.md) 中的 `scripts/verify_article.py` 检查块覆盖、逐字一致、图表文字与链接，修复错误后再交付。它只读输入，不能替代对修改理由、图示方向和版面的人工审查。没有这种源稿时按同样标准逐段人工核对，不编造校验统计。

发布范围按当前任务及已有会话授权判断。指定本地预览地址，只更新并核验该地址；不要将之前的部署记录视为公网发布授权，也不要将本次地址永久固定成其他任务的部署目标。

完成时说明所依据的版本、移除的形式、必要的连接修改和实际交付位置。用户指出两版不一致时，先查明实际差异；若由改编造成，说明原因并用逐段比对纠正，不用继续大幅重写来解释差异。
