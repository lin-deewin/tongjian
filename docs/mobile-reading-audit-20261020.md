# 手机阅读优化调研与实施建议

日期：2026-10-20。基于当前本地工作区；本轮只做调研、布局检查和建议，没有修改产品代码或发布线上。

## 1. 屏幕适配对象

网页布局按 CSS 视口宽度适配。厂商标注的物理分辨率、屏幕英寸、OLED/LCD、刷新率不能直接决定网页列数。设备像素比影响画布清晰度和成本；系统显示缩放、浏览器窗口、折叠状态影响实际可用宽度。以下为代表性测试视口，不是市场份额排名或所有机型规格表。

| 场景 | 测试视口 CSS px | 适配策略 |
| --- | --- | --- |
| 老款小屏、极窄窗口 | 320×568 | 内容一列；标题换行；工具允许折行；不能缩小正文救布局 |
| 常见窄屏安卓 | 360×800 | 作为手机最低主体验基线；正文边距约16px |
| 小尺寸 iPhone 等 | 375×667 | 检查短屏首屏、工具遮挡和键盘弹出 |
| 常规 iPhone 尺寸档 | 390×844、393×852 | 主设计样本；检查安全区及Safari动态工具栏 |
| 常见大屏安卓尺寸档 | 412×915 | 检查大字体、系统缩放和国内浏览器 |
| 大屏 iPhone 尺寸档 | 430×932、440×956 | 保持字号和点击区，不机械增大所有间距 |
| 折叠屏外屏 | 320–400宽 | 依实际可用宽度落入窄屏布局；不按设备品牌判断 |
| 折叠屏内屏、小平板 | 600–900宽 | 按内容容器判断列数；保留单列阅读选择 |
| 手机横屏 | 844×390等 | 单独处理矮屏，减小常驻工具高度；不因宽度变大强制桌面密度 |

常见宽度还包括384、402、414等；流式布局应覆盖连续宽度，而非只对表中点值生效。候选布局边界可先用360/600/900，最终按内容是否挤压确认；现有600/700/800/900/1050等断点应逐步核对责任，不一次性全局替换。

实机覆盖优先Safari、安卓Chrome、微信内置浏览器，再按实际访客补充华为、小米、荣耀等浏览器。屏幕尺寸模拟不等于这些浏览器的兼容性验收。

## 2. 已核对的当前问题

- Chromium触屏模拟检查320×568、360×800、375×667、390×844、412×915、430×932、768×1024、844×390三类页面，共24组，页面根节点均未出现横向溢出。仅代表这三个页面和默认状态。
- `river.css`的小屏规则仍保留310px事件面板、252px内部滚动列表；它排在290px画布之前。在390宽页面中，事件面板顶部约814px，画布顶部约1124px。列表先于图表，用户很难立即理解长河。
- 长河筛选下拉约31px高，前后年按钮约37px；年表事件标题在小屏规则下为12px。需要增加可读性和有效点击面积，而不是只满足无溢出。
- 正文样本原文19px、白话18px，已有可读的字号基础；返回年表按钮约32px，底部工具按钮约31px高。正文内注释标记约10px、元素框约14px高，应重点实机验证误触。行内注释不能简单统一加高度而打乱行距，可提供独立注释操作。
- `river.js`触摸命中半径最低18px，密集点仍可能互相抢占。横拖阈值只看水平移动超过7px，没有完整方向锁定；虽然canvas已有`touch-action:pan-y`，斜向滑动仍需验证是否短暂误改年份。
- 长河全量事件JSON约3.9MiB，为磁盘未压缩大小，不能当作网络传输大小；当前仍需下载、解析全量事件。低端设备解析耗时、弱网等待需要测量。
- 画布按完整设备像素比渲染，高DPR设备成本更高；已有离屏暂停、后台暂停、减少动态效果偏好和约30fps节流，后续应保留这些优化。
- 横屏844px宽会越过部分800px手机规则；需要验证低高度下的对照列、工具和弹层是否合适。

证据：`artifacts/mobile-audit-20261020/metrics.json`，以及该目录首页、年表、正文截图。检查脚本本轮临时执行，尚未并入回归脚本。

## 3. 阅读器优先级

### P0：读得清楚、点得准确、位置不丢

1. 年表事件标题建议15–16px，辅助信息12–13px；正文保留目前18–19px基础和字号调整，行高约1.85–2.0，边距14–20px随容器变化。先通过真实段落比较，不全局缩放。
2. 常用独立按钮有效点击区目标44–48 CSS px；视觉图标可以小，点击区域不能挤在一起。WCAG 2.2 AA的24×24最低标准带间距及行内等例外，44–48是本项目舒适性目标，不混称强制标准。
3. 手机继续同组原文、白话上下排列；保留仅原文、仅白话。横屏和折叠屏按可读列宽决定是否并列，不仅按设备宽度分类。
4. 保留底部上一年、工具、下一年；处理`safe-area-inset-bottom`、工具展开、键盘及浏览器工具栏。最后一段及其链接必须能完整滚动到工具栏上方。
5. 字号、模式、注释开关改变后，按稳定段落锚点及段内相对位置恢复阅读位置；返回年表继续恢复原事件附近。
6. 输入框检查iOS聚焦自动放大，手机输入文字建议至少16px。不得禁用用户页面缩放；验证200%缩放/大字号时操作可达。
7. 短屏和横屏按高度补充布局规则；固定尺寸弹层改为视口约束和可滚动内容。`svh`适合稳定高度，`dvh`适合跟随可用高度，不无差别替换。

### P1：连续阅读

- 地图点开后提供可缩放大图并能回到原段落；避免缩略图文字被迫承担阅读任务。
- 人物链接、注释、文本选中、摘记菜单检查手势冲突；选择文本时不误跳人物页。
- 模式、字号、主题偏好继续保存；弱网加载下一年给出明确状态和可重试入口。
- 同年跨卷续篇、缺译提示、史论及追叙说明保持可见，不因手机精简而丢失。

## 4. 历史长河的手机结构

建议顺序：标题与简短说明 → 当前年份/朝代与主要筛选 → 图表 → 全书概览与年代导航 → 所选年份事件列表 → 阅读入口。

- 图表成为主要浏览区域。手机建议先试200–240px高度，矮屏再缩减；以可用高度验证，而非直接写成固定最终值。
- 事件列表放到图下，默认展示3–5条，可展开全部，使用页面共同滚动，减少内外两套竖向滚动争抢。展开内容不删除任何事件。
- 朝代和主题为第一层筛选；缩放、更多条件折叠到第二层，保留当前状态提示。全书比例朝代标签仍可保留，但精确选朝代提供独立且足够大的入口。
- 手指横滑浏览年代，竖滑滚动页面；先判断方向，再开始横拖。处理pointercancel、多指触摸和旋转中断，不能用全局preventDefault封住页面。
- 点事件先选中并在图下显示完整标题和阅读按钮；只有明确点击阅读入口才进入正文。减少手指遮挡和点错后跳走。
- 按屏幕密度自动选择初始时间跨度；全书视图适合看分布，近景看单个事件。远景密集点可聚合并显示数量，放大后恢复单事件，聚合不是删减史料。
- 常驻清晰的上一年/下一年、年份直达、朝代选择，确保不需要精准拖滑块也能完成定位。Canvas事件需要对应DOM列表作为可访问替代。
- 阅读返回长河时保留中心年代、缩放、筛选、事件和页面位置；不能每次回到默认年份。

性能方向：先测量，再决定改造范围。候选措施包括首次进入长河时加载事件、按年代拆包、只绘制可见范围、静态层缓存、拖动每帧最多一次绘制、限制Canvas DPR（例如先比较上限2的清晰度与开销）、空闲停止装饰动画。拆包必须保留稳定事件ID和完整来源索引。

## 5. 实施和验收

顺序：第一批阅读字号/点击区/安全区/横屏 → 第二批长河手机排列与手势 → 第三批根据性能记录拆数据或缓存绘制。每批独立验证，保留桌面布局。

自动回归：宽度320/360/375/390/393/412/430/440，折叠与平板600/768/900，横屏844×390；加入断点两侧599/600/601、799/800/801。覆盖首页长河、年表、动态正文、独立年份静态页、人物时间线及专题图表。

真实浏览器场景：首屏进入正文；长段古文/白话切换；注释开关及长注；地图放大返回；上一年下一年及跨卷续篇；字号变化恢复段落；键盘弹出收起；系统大字体；安全区；长河横拖/竖滑/斜滑；多指与取消；密集事件选择；筛选后返回；屏幕旋转与折叠展开；弱网失败和重试。

性能目标候选：中端安卓拖动响应接近屏幕刷新节奏，至少保持稳定30fps；手势开始不明显卡顿；加载中能操作导航；记录LCP/INP、长任务、事件解析与绘制耗时。LCP≤2.5s、INP≤200ms可作为真实用户75分位目标，不能用一次桌面模拟宣称已达成。

实际用户尺寸分布可补充匿名的视口宽高分桶与方向统计，不使用设备指纹。此前的UV统计只有设备类别，不能推算本站屏幕市场分布；本轮未改变统计采集。

本轮未完成iOS/微信/华为等实机验收，未跑全书数据校验，因为未修改正文或数据。没有把Chromium尺寸模拟当作全设备兼容结论。
