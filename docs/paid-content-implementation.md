## 邮箱验证阶段的账号流程（历史记录）

本节以前文开发历程之后的最新要求为准：邮箱注册必须通过验证码。已增加注册验证码输入与发送表单，支持常见邮箱和企业邮箱；先发送、验证后再原子创建账号并保存 `email_verified_at`。注册验证码与旧登录验证码通过用途字段和 HMAC 内容隔离。10 分钟过期、60 秒重发、重发旧码失效、5 次错误失效、一次消费、并发只创建一个账号均已测试。数据库增量迁移 `accounts.0002` 已在本地应用，不重建或删除原账号数据。

最新验证：73 项 PostgreSQL 测试通过；真实浏览器完成发送注册邮件（本地文件后端）、填写验证码与密码注册、模拟购买、退出后密码登录和找回密码；禁用 JavaScript 的注册也通过。[最新浏览器报告](../artifacts/commerce/20261015-102259-4be720/qa-report.json)。SMTP 未配置，真实收件箱投递未完成；开发页面明确显示测试模式，不将测试文件称为已投递邮件。配置受限 SMTP 后开发环境自动使用真实 SMTP，配置步骤见后端手册。以下不验证邮箱的注册描述为前一次实现记录，已被本段替代。

用户要求普通注册与登录后，已将读者界面改为独立的 `/tongjian/account/register/`（邮箱、密码、确认密码）和 `/tongjian/account/login/`（邮箱、密码）。导航分别显示“登录”“注册”，登录后显示“我的购买”。使用 Django 原生服务端表单、CSRF 与密码验证/加盐哈希，密码长度至少 12 字符，支持重复邮箱、错误密码、密码不一致的页面提示和 IP/邮箱维度限流。注册成功后自动登录，回到原购买页面；登录失败不会创建账号。

找回密码使用邮件一次性限时链接（24 小时），包含申请、已发送、重设、成功/失效页面。旧验证码账号通过邮箱证明身份后设置密码，沿用原 UUID，不新建账号，不迁移或覆盖订单与权益；更改密码会使其他旧会话失效。管理员仍使用独立后台入口。旧 OTP 接口保留兼容，当前读者注册/登录页面不再调用它们。

此前一版注册不依赖发信；现已按最新要求加入注册邮箱验证码，当前验证码与找回密码均采用 `backend/test-mail/` 文件测试后端。SMTP 真实投递仍待配置，密码登录无需发信。

最新验证：64 项 PostgreSQL 后端测试通过（包括密码注册/登录、重复邮箱、弱密码、CSRF、登录限流、旧账号重设、过期及复用链接、旧会话失效）；无需数据库模型迁移。真实 Chromium/Caddy/Gunicorn 隔离测试已完成注册→模拟购买→退出→错误密码提示→密码登录→找回并重设密码→再次登录下载已购 PDF；注册/登录在禁用 JavaScript 时也通过。1440/390/320px 三种视口检查注册、登录、找回页面及五个公开页面导航，无横向溢出。证据：[交易与账号浏览器报告](../artifacts/commerce/20261015-101321-781a52/qa-report.json)、[导航及表单截图](../artifacts/commerce/password-navigation/report.json)、[后端测试日志](../artifacts/commerce/unit-tests.txt)。以下原有阶段记录中的 OTP 检查是历史实施，不代表当前用户界面。
