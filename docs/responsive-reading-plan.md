# 通鉴网站：手机与电脑浏览器适配方案

日期：2026-10-20。状态：已在本地实施，未发布线上。实现内容、验证证据与剩余实机验收见[实施记录](responsive-reading-implementation.md)。历史长河改版随后由用户撤回，已恢复原版布局和交互；下文长河部分仅保留为历史方案，不继续实施。其余部分保留方案及验收约定，实机浏览器覆盖和真实性能目标不因本地自动化通过而视为完成。

## 1. 目标与基本约定

同一个网站、同一套网址和内容数据。普通页面采用响应式布局，历史长河共享数据和定位状态，分别组织手机与桌面交互。不另建手机域名，不复制维护两套正文。

保留纸色、墨绿、简洁边框、年表入口、独立整页阅读、桌面左右对照、手机同组上下对照、共同滚动、字号、注释、模式切换、事件锚点及返回位置。不得恢复右侧抽屉或双页书美化。

**最高优先级的排版要求：所有界面文字和正文保持横排。空间不足时调整布局，禁止将横排文字挤成一字一行的“竖条”。**

本方案承接[前期检查记录](mobile-reading-audit-20261020.md)。本方案的初始断点统一为600和960 CSS px，替代调研记录中的候选边界；最终根据内容容器和实测确认。

## 2. 横排文字保护规则

### 2.1 必须区分两类文字

| 类型 | 示例 | 空间不足时的处理 |
| --- | --- | --- |
| 短操作文字 | 返回年表、上一年、下一年、工具、筛选、登录、朝代名 | 整体横排、不拆字；按钮换到下一行或收进菜单 |
| 长内容文字 | 事件标题、年号、卷名、说明、正文、长注释 | 在足够宽的内容区域中自然横向换行；区域不足时移至整行 |

“保持横排”不等于所有内容强制一行。长标题可以横向排成两三行，但不能被剩余宽度挤成每行一个字。原文、白话、年号和事件标题不删减；确需简短导航文案时，应保留明确含义和完整内容入口。

### 2.2 布局退让顺序

1. 先减少装饰性间距，保持文字字号和舒适点击区。
2. 将并排工具换为多行，把次要操作放入菜单。
3. 将左侧年份栏、右侧标签等移到标题上方或下方，释放整行宽度。
4. 原文、白话从左右对照改为同组上下对照。
5. 数据表等确实需要二维关系的内容，在独立区域提供横向滚动；页面整体不横向滚动。

不得通过无限缩小字号、压扁文字、裁切正文、隐藏溢出或禁止浏览器缩放解决拥挤。不能只加`white-space:nowrap`而让按钮溢出；必须同时提供换行、堆叠或折叠布局。

### 2.3 CSS实现约束

- 界面和正文维持`writing-mode:horizontal-tb`；不使用文字旋转或逐字插入换行实现适配。
- 短按钮、年份数字和朝代短标签使用`white-space:nowrap`，必要时设置`flex-shrink:0`；父级允许换行或改变排列。
- 弹性内容区使用`min-width:0`，网格使用`minmax(0,1fr)`，并搭配最小可读列宽及堆叠条件。`min-width:0`只能防溢出，不能独自保证不挤成竖条。
- 长中文标题和正文使用正常换行，避免全局`word-break:break-all`或`overflow-wrap:anywhere`。URL、来源标识等连续长字符串单独允许断行。
- 不给长标题和正文设置固定高度；换行后容器自然增高。短操作区建议44–48px有效点击高度。
- 双栏对照每栏目标至少约18个当前字号的汉字宽度；放大字号或容器变窄后不满足时，应上下排列。该阈值为初始设计值，需用实际段落校准。
- 年表事件标题区域目标至少约12个汉字宽度；不足时将年份信息改为卡片顶部横排，而非继续压缩事件区。
- 输入框文字建议至少16px，验证iOS聚焦行为；不设置阻止用户缩放的viewport参数。

以下只说明布局原则，实际应按现有组件选择器局部接入，不能作为全站覆盖样式直接粘贴：

```css
.action-label {
  writing-mode: horizontal-tb;
  white-space: nowrap;
  flex-shrink: 0;
}

.action-group {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}

.content-title {
  min-width: 0;
  white-space: normal;
  word-break: normal;
  overflow-wrap: normal;
}
```

## 3. 适配依据与布局档位

依据CSS可用宽度、可用高度、组件容器宽度、字体大小和触摸能力调整，不按品牌或User-Agent强行分站。CSS负责普通布局；Canvas尺寸和长河交互由JavaScript配合。窗口缩放、旋转及折叠状态变化时即时调整，不刷新整页。

| 条件 | 页面策略 |
| --- | --- |
| 小于600px | 单列优先；手机对照上下排列；次要操作折叠 |
| 600–959px | 中间布局；工具允许换行；正文按列宽决定排列 |
| 960px及以上 | 桌面布局；空间足够时正文左右对照、长河列表并排 |
| 横屏且高度小于500px | 另加矮屏规则，减少常驻工具占用，限制弹层高度 |
| 粗指针、无悬停设备 | 扩大触摸区，支持点击预览；不依赖悬停完成操作 |

断点是默认布局起点，不强迫内容塞进对应列数。桌面窗口缩窄也可进入手机布局；宽屏触摸设备仍需适合手指操作。混合输入设备同时支持鼠标和触摸，不能仅靠一次能力检测锁死交互。

设备像素比仅用于图片和Canvas清晰度及性能控制，不用于决定正文大小。安全区使用`env(safe-area-inset-*)`并验证viewport设置；弹层按需使用`dvh`及兼容回退，稳定区域按需使用`svh`。

## 4. 阅读器

- 默认原文19px、白话18px，保留现有字号调整；行高约1.85–2.0。字号范围沿用当前功能，经实测再调整，不无关更换字体。
- 手机正文水平边距约14–20px；电脑居中限制内容最大宽度，避免超宽显示器上单行过长。
- 手机同组先原文后白话，桌面同组左右对照；两种布局都使用页面共同滚动。
- 顶部保留返回年表和简短年份信息，长卷名可另起整行；不得挤压“返回年表”按钮。
- 底部保留上一年、工具、下一年。三者文字均不拆行；极窄屏优先简化非必要间距或调整排列。正文底部预留工具栏实际高度和安全区，最后一段、链接及注释不能被遮挡。
- 工具内容在页面内展开或使用适合手机的底部面板，避免常驻占满屏幕；不引入阅读右侧抽屉。长面板内部允许滚动，关闭后恢复焦点和位置。
- 注释、人物链接和摘记避免争抢手势；行内文字保持正常行距，较小注释标记另提供方便的注释操作。
- 切换字号、模式、注释和横竖屏时，以稳定段落锚点及段内偏移恢复上下文；不能只记旧scrollY。
- 保留同年跨卷续篇、缺译、史论和追叙提示。地图可点开看大图，关闭后回到原段落。

## 5. 年表、筛选与人物页

- 手机事件标题15–16px，辅助信息约12–13px，标题完整横向换行。
- 窄屏优先采用“年份与年号在上、事件列表在下”的卡片结构，消除左侧窄年份栏导致年号和标题变竖条的问题。宽度足够时保留当前左右信息布局。
- 卷名选择器占整行；前后卷与说明组成独立操作行，不能争抢卷名宽度。
- 搜索在小屏可占整行，年份直达与筛选在下一行；筛选项太多时按需展开。不要为保持一行压缩搜索输入区或按钮标签。
- 人物时间线保留横向浏览及纵向布局选择；卡片有合理宽度，窄屏不把完整人物经历塞进几字宽的列中。
- 人物简介、长年号、长标题及专题图表都遵循横排保护规则，不仅优化首页和阅读器。

## 6. 历史长河

### 6.1 手机端排列

标题与简短说明 → 当前年份及主要筛选 → 河流图表 → 全书年代概览 → 当前年份事件 → 阅读入口。

- 调整当前310px事件面板排在图表之前的结构，图表优先出现。
- 图表初始试验高度200–240px；矮屏另作调整，以可读性和触摸准确度定稿。
- 事件默认显示3–5条，展开后跟随页面滚动，避免嵌套竖向滚动。所有事件仍可访问。
- 主题、朝代为主要筛选；缩放等次要选项按需展开。短标签保持整块横排，布局不足就换行。
- 年代概览中的短朝代不能因比例很窄被逐字竖排。提供独立朝代选择入口；概览标签可以分层排列或省略部分视觉标签，但不改变时间比例或隐藏导航能力。
- 完整事件标题在图下列表或详情区显示；Canvas文字不能无限缩小或堆叠到不可读。

### 6.2 桌面端排列

保留宽幅图表、并排事件列表、完整工具和鼠标悬停预览。列表标题空间不足时允许横向多行并增加行高；不要只靠省略号承担事件识别。切换为上下结构后不重复生成两份事件内容和焦点入口。

### 6.3 交互与性能

- 横滑浏览年代、竖滑滚动页面；方向明确后再开始横拖。处理斜滑、pointercancel、多指和旋转，不全局阻止默认滚动或缩放。
- 点选事件先展示完整标题，再明确点击进入阅读。保留DOM事件列表，确保不用精确点Canvas也能访问。
- 全书远景显示分布或聚合数量，近景展开单事件；聚合不删除数据、不改变事件来源绑定。
- 返回后保留中心年代、缩放、主题、事件和滚动位置。
- 首先记录弱网加载、事件JSON解析、拖动帧耗时和长任务；再决定按年代拆包、缓存静态绘制、每帧合并更新和限制DPR。
- 保留现有离屏暂停、后台暂停及减少动态效果偏好；手机闲置时减少持续装饰动画。

## 7. 文件范围与实施顺序

| 批次 | 范围 | 主要落点 |
| --- | --- | --- |
| 第一批 | 横排文字保护、字号、点击区、安全区、窄屏年表 | `dist/reader.html`、`dist/yearbook.css`、相关阅读样式；必要的状态恢复在`dist/app.js` |
| 第二批 | 长河排列、标题、筛选、触摸和返回状态 | `dist/index.html`、`dist/river.css`、`dist/river.js` |
| 第三批 | 独立年份页、人物及专题一致性、性能 | 对应共享样式与页面生成脚本；按实测决定数据拆分 |

先确认样式加载顺序和现有覆盖关系，局部修改，避免不断追加互相冲突的媒体查询。独立年份等生成页面要修改生成源并重建，不能只手工改某个输出页造成下次重建丢失。共享数据、事件ID、年份排序规则和来源内容保持有效。

每批独立验证；本地开发不自动发布。发布另按用户要求及现有服务器流程执行。

## 8. 验收标准

### 8.1 尺寸与浏览器

- 代表宽度320、360、375、390、393、412、430、440、600、768、960、1280、1440px。
- 覆盖599/600/601、959/960/961px及保留的旧断点两侧，检查中间宽度，不只检查固定截图。
- 手机横屏844×390、短屏320×568；浏览器200%缩放、阅读最大字号和系统大字体。
- Safari、安卓Chrome、微信内置浏览器优先实机检查；按实际访客补充华为、小米等浏览器。桌面覆盖Chrome、Edge、Firefox及Safari的可用环境，未测项目如实记录。

### 8.2 横排文字为发布阻断项

以下任意情况出现即不通过：

1. “返回年表”“上一年”“下一年”“筛选”等短操作文字被拆成一字一行或非预期多行。
2. 年份数字、短朝代标签拆开竖向堆叠；长年号因侧栏太窄形成竖条。
3. 事件标题或正文因列宽不足连续多行只有一两个汉字，而该内容本来可通过上下布局获得整行宽度。短句、标点或最后一行自然余字不算此问题。
4. 通过缩小字号、裁切文字、隐藏溢出掩盖上述问题。
5. 表面横排但按钮越界、相互覆盖，或点击区域被邻近元素挤掉。

测试内容至少包含：最长卷名、较长年号、长事件标题、多标签、长注释、长URL、同年跨卷续篇、缺译提示。用浏览器Range测量短操作文字是否仍为单行，并结合截图检查长标题行宽；不能仅断言`writing-mode`或页面没有横向溢出就判定通过。

### 8.3 功能与性能

- 年表→事件→阅读→返回位置正确，浏览器前进后退正常。
- 字号、注释、模式、主题、地图、人物和摘记操作后，正文仍可读且上下文不丢。
- 键盘弹出、工具展开、旋转后，按钮可达，正文末尾不被遮挡。
- 长河横拖、竖滑、斜滑、事件选择、筛选及返回状态正常；键盘和DOM列表可替代Canvas操作。
- 桌面左右对照与共同滚动不退化；手机没有因新增宽度规则误进入窄双栏。
- 自动化尺寸检查配合真实截图和实机手势；不把简化DOM或桌面模拟冒充手机实机验收。
- 根据改动运行JavaScript语法、阅读导航及相关浏览器检查；修改生成脚本则执行对应重建与一致性检查。未改变正文数据时不为样式调整重建全书。

交付应附修改文件、实际验证尺寸与浏览器、横排文字样本截图，以及未验证项。以“文字正常横排、内容可完整读到、操作可准确完成”为通过标准。
